# Workspace — Version 2.0.0

**Release date:** 2026-07-03
**Branch:** main
**Type:** Major release (`_.0.0`) — complete re-architecture of storage and accounts

---

## Overview

Version 2.0.0 removes the backend entirely. There are **no accounts, no login, and no
Firebase**. Every workspace is now stored as **plain folders and Markdown files** — either
in a folder on your computer (File System Access API) or mirrored to your **Google Drive**.
The point of the rewrite: your data stays yours. It remains readable and editable in any
text editor, and keeps working even if this app is uninstalled.

The block editor, nested pages, and multi-view databases are unchanged from v1.2 — only the
persistence layer, account model, and app shell were rebuilt.

## On-disk workspace structure

Each workspace is a self-describing folder tree — no JSON anywhere in your data:

```
<Workspace Title>/            the folder you pick / create (its name is the title)
├── info.md                   appearance settings (theme, accent, font, page background, description)
├── Upload/                   uploaded images & file attachments
│   └── sunset.jpg
├── Space/                    live pages
│   ├── Meeting Notes.md      a page with no children
│   └── Homework/             a page WITH children → a folder
│       ├── master page.md    the "Homework" page's own content
│       ├── Essay.md
│       └── Math/
│           ├── master page.md
│           └── Problem set 1.md
├── trash/                    deleted pages (restorable)
└── archive/                  archived pages (restorable)
```

- Pages are `.md` files with a small **YAML frontmatter** header (`id`, `title`, `icon`,
  `cover`, `order`, `type`, and — for databases — the full `db:` structure).
- A page with children becomes a **folder** holding `master page.md` plus its children.
- Deleting a page **moves** its file to `trash/`; archiving moves it to `archive/`; both
  keep `parentId` in frontmatter so they restore to their original place.

## Storage options

|                 | **Local folder**                          | **Google Drive**                          |
|-----------------|-------------------------------------------|-------------------------------------------|
| **Mechanism**   | File System Access API                    | Drive API (`drive.file` scope)            |
| **Where**       | A folder you choose on this computer      | A real, browsable folder in your Drive    |
| **Reconnect**   | Handle in IndexedDB + cookie pointer      | OAuth token (GIS) + cookie pointer        |
| **Browser**     | Chromium (Chrome, Edge, Brave)            | Any browser                               |

The active workspace and theme are remembered in small **browser cookies**; the File System
handle lives in IndexedDB (it can't be cookie-serialized), and the Drive token in
`sessionStorage`.

## What's new in 2.0.0

### Architecture
- **Removed Firebase** — no `firebase.js`, `storage.js`, or Firestore. Dependency dropped.
- **Removed accounts / the user concept** — no `auth.jsx`, no sign-in screen, no `user`.
- **Removed sharing & notifications** — workspace/document sharing, the shared panel, the
  inbox, members and ownership transfer are all gone.
- **Two workspace types only** — Local folder and Google Drive.

### Storage — Markdown on disk
- New `markdown.js` serializer converts the page tree ⇄ a folder-of-Markdown tree.
- `localfs.js` and `cloudstorage.js` read/write the same folder structure (diffed writes,
  deletion reconcile, empty-folder pruning).
- **No JSON** is used for workspace data — settings and databases use YAML frontmatter.
- **`info.md`** — per-workspace appearance file: theme, accent, font, custom page background
  (uploadable image), and a workspace description.
- **`trash/`** and **`archive/`** folders — deleting or archiving a page moves its file there
  instead of erasing it; restore moves it back.

### App shell
- **Homepage** — shown when no workspace is connected; lists previously connected workspaces
  (Open / Unlink) and a single "Connect a workspace" block (name + description + Local/Drive).
- **Create Local by name + location** — you name the workspace and pick a location; the app
  creates the named folder for you.
- **Animated welcome background** — drifting aurora orbs + subtle grid, theme-aware.
- **Sidebar footer** — Settings and "Close workspace" pinned at the bottom.
- **Trash, Archive, and Templates are full pages** (previously modals).
- **Cookie-based persistence** for the active workspace pointer and theme.

### Settings
- Light / dark mode, 7 accent themes (Indigo, Blue, Ocean, Forest, Rose, Sunset, Violet).
- **Font** — Default (Sans), Serif, or Monospace, applied to page content.
- **Page background** — upload a photo shown behind pages (stored in `Upload/`).
- **Description** — a short workspace note, saved in `info.md`.
- On-disk file location of the current page shown in the topbar (Local workspaces).

### Unchanged from v1.2
Block editor (text, headings, lists, to-dos, toggles, quotes, callouts, dividers, code,
images, files, bookmarks, sub-pages), multi-view databases (table / board / gallery / list /
calendar), slash commands, instant search, favorites, `.docx` import, and keyboard shortcuts.

## Project structure

```
index.html                  Boot screen + root mount point (keeps the Google Identity script)
vite.config.js              Vite config (vendor chunk splitting)
src/
  main.jsx                  Entry point
  App.jsx                   Restores theme, renders the workspace (no auth gate)
  workspace.jsx             Full app: homepage, editor, databases, sidebar, full pages, modals
  markdown.js               Workspace ⇄ folder-of-Markdown serialization (pure, testable)
  localfs.js                Local folder storage (File System Access API + IndexedDB)
  cloudstorage.js           Google Drive folder-tree mirror
  cookies.js                Tiny cookie helpers (active-workspace pointer + theme)
  styles.css                Design tokens, components, dark mode, themes
versions/
  v2.0.0.md                 This document
```

Removed since v1.2: `src/auth.jsx`, `src/firebase.js`, `src/storage.js`,
`public/oauth-callback.html`, `.env` / `.env.example`, `SETUP.md`.

## Running locally

```bash
npm install
npm run dev
# → http://localhost:5173
```

No environment variables. Pick a **Local folder** (Chromium) or **Google Drive** from the
homepage. Local data is plain Markdown you can open in any editor.
