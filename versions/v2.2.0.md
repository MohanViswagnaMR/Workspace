# Workspace — Version 2.2.0

**Release date:** 2026-07-08
**Branch:** main
**Type:** Minor release (`0._.0`) — first-impression & onboarding

---

## Overview

Beta testers landing on the site couldn't tell what the app was or what they
could do with it: there was nothing to look at, and the very first action
demanded either a folder-access permission or a Google sign-in. Version 2.2.0
fixes the first impression end to end by splitting the entry into two pages —
a **Welcome page** (a normal website that explains the application, shown when
the browser has no workspace data yet) and the **Start page** (the familiar
connect screen, shown when it does) — plus a one-click **demo workspace** that
runs purely in memory, new **About** and **Self-hosting** pages, a version
badge in the navbar, and two workspace polish items (new workspaces start
empty; sidebar chevrons only on pages with subpages).

No data format changed. Pages are still plain Markdown files.

---

## New in 2.2.0

### Welcome page — a real landing for first-time visitors
If the browser holds **no workspace data** (no connected workspaces, no active
pointer, no Drive session), the app now opens on a proper website-style landing
page: a hero that explains the application, six feature cards, a "your data is
just files" section with the folder-tree example, and a navbar with **About**,
**Self-hosting**, **Docs**, GitHub and the version badge. Two calls to action:
**Get Started** (→ the start page) and **Try the demo**.

### Start page — the familiar connect screen
Returning users (any workspace data in the browser) land directly on the same
screen as before — "Your notes, as plain Markdown.", the workspace list, and
the connect panel — visually unchanged from 2.1.1 except for two navbar
additions: a **Welcome** link (before Docs) that reopens the landing page on
demand, and the version badge. **Get Started** on the landing always returns
here, so the two pages round-trip cleanly.

### About & Self-hosting pages
Two new site pages, styled like the Docs: **About** (what the app is, the
principles — files over databases, no accounts, no lock-in, local-first — and
the tech stack) and **Self-hosting** (build & deploy the static `dist/` to any
host, HTTPS requirements, optional Google Drive OAuth setup with your own
client ID in `src/cloudstorage.js`, sub-path notes, updating).

### Try the demo — a zero-commitment sandbox
A **Try the demo** button on the welcome page opens a fully working workspace
instantly — no sign-up, no folder picker, no Google sign-in. It is the sample
workspace (Getting Started, Tasks board, Reading List, Meeting Notes, Team
Wiki) mounted **purely in memory**:

- Nothing is ever written to disk, Drive, cookies, or the workspace pointer —
  a reload lands back on the welcome page.
- An amber banner across the top says you're in the demo, with
  **Keep this workspace** and **Exit demo** buttons.
- The storage badge shows **🧪 Demo** and the save pill reads **Not saved**
  (instead of pretending to save).
- The welcome tour fires in the demo for first-time visitors, exactly as it
  would in a real workspace.
- **Exit demo** returns a fresh visitor to the welcome page, and a user who
  already clicked Get Started to the start page.

### Keep this workspace — demo → real conversion
"Keep this workspace" (from the banner, the storage badge menu, or the
workspace switcher) opens the connect dialog in a special mode: it explains
that everything made in the demo will be saved, and creating a **Local
folder** or **Google Drive** workspace carries the demo's *current* content —
including any edits — into the new workspace instead of re-seeding it.

### Version badge
Both navbars (welcome and start page) show the current version — **v2.2.0** —
as a small pill next to the GitHub button, linking to the release notes. The
number is injected at build time from `package.json` (`__APP_VERSION__` via
Vite `define`), so future releases only bump `package.json` and the badge
follows.

### New workspaces start empty
Creating a Local or Drive workspace no longer seeds it with the sample pages
(Getting Started, Tasks, Reading List…). A fresh workspace opens on the Home
dashboard with no pages, ready for your own structure. The sample content now
exists **only in the demo** — and comes along if you keep the demo.

### Sidebar: dropdown only where it belongs
Pages without subpages no longer show an expand chevron in the sidebar — the
arrow appears only when a page actually contains subpages (and shows up
automatically when the first subpage is added). Leaf rows keep a same-width
spacer so icons and labels stay aligned, and the stray "No pages inside" row
is gone.

## Running locally

```bash
npm install
npm run dev            # dev server — service worker disabled
# or, to exercise the PWA:
npm run build && npm run preview
```

No environment variables. First visit lands on the **Welcome** page — click
**Try the demo** for an instant sandbox, or **Get Started** to connect a
**Local folder** (Chromium) or **Google Drive** workspace.
