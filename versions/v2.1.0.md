# Workspace — Version 2.1.0

**Release date:** 2026-07-04
**Branch:** main
**Type:** Minor release (`_._.0`) — Progressive Web App + app rename

---

## Overview

Version 2.1.0 turns Workspace into an installable **Progressive Web App**. You can
now install it to your desktop or phone, launch it in its own standalone window,
and open it offline — the app shell is cached by a hand-rolled service worker. No
data format changed, and nothing new is sent anywhere: your notes are still plain
Markdown in a local folder or your Google Drive.

This was implemented **without any new dependencies**, in keeping with the
project's minimal, hand-rolled style (no `vite-plugin-pwa` / Workbox).

The app is also now simply called **Workspace** (previously "Workspace — Notes &
databases as Markdown").

---

## What's new in 2.1.0

### Installable
- **Web app manifest** (`public/manifest.webmanifest`) — name, description, theme
  and background colours (dark + violet, matching the default look), `standalone`
  display, and a full icon set.
- **App icons** — a violet, geometry-drawn `◧` mark (the app's boot logo) rendered
  as `icon-192.png`, `icon-512.png`, a full-bleed `maskable` variant, an
  `apple-touch-icon.png`, and a scalable `icon.svg` (now also the favicon).
- **Apple / mobile meta tags** in `index.html` — `apple-touch-icon`,
  `apple-mobile-web-app-*`, `mobile-web-app-capable`, and a `theme-color`, plus
  `viewport-fit=cover` for notched displays.

### Offline
- **Service worker** (`public/sw.js`) — precaches the app shell on install and
  serves Vite's hashed JS/CSS **stale-while-revalidate**; navigations are
  **network-first** with an offline fallback to the cached shell. Old caches are
  pruned on activate.
- **Auth & sync never hit the cache** — the worker only intercepts same-origin
  requests, so Google Identity Services (`accounts.google.com`) and the Google
  Drive API (`googleapis.com`) always go straight to the network.
- **Registered in production builds only** (`src/main.jsx`, guarded by
  `import.meta.env.PROD`), so the dev server's hot reload is never affected.

### Update model
- Classic service-worker lifecycle — no forced reloads or mid-session asset
  swaps. A new version activates once all tabs are closed. The `CACHE` constant in
  `sw.js` (currently `workspace-v2.1.0`) is bumped per release to refresh the
  shell.

### Naming
- The application is now called simply **Workspace**. The browser tab title
  (`index.html`), the PWA manifest `name`, and the README heading were shortened
  from "Workspace — Notes & databases as Markdown" to "Workspace". The manifest
  `short_name` was already "Workspace", and the descriptive `description` tags are
  unchanged.

## Notes & limitations

- **Local-folder editing offline** works fully (File System Access API is local).
  **Google Drive** workspaces still need the network to sync, by design.
- **Sub-path deploys:** the manifest and worker assume the site is served from the
  origin root (`/`). If you set a Vite `base`, update the paths in
  `manifest.webmanifest`, `sw.js`, and the registration in `main.jsx`.
- The service worker is a no-op during `npm run dev`; verify the PWA with
  `npm run build && npm run preview` and the browser's Application/Lighthouse tab.

## Running locally

```bash
npm install
npm run dev            # dev server — service worker disabled
# or, to exercise the PWA:
npm run build && npm run preview
```

No environment variables. Pick a **Local folder** (Chromium) or **Google Drive**
from the homepage.
