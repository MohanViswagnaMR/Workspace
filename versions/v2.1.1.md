# Workspace — Version 2.1.1

**Release date:** 2026-07-08
**Branch:** main
**Type:** Bug-fix release (`_._._`) — editor correctness & polish

---

## Overview

Version 2.1.1 is a bug-fix release focused on the block editor. It fixes a
storage round-trip bug that created phantom empty blocks, makes Enter split
paragraphs properly, adds link detection, forward-delete merging, a right-click
formatting menu for selected text, multi-block mouse selection, and keeps
pop-up menus on screen. No data format changed — pages are still plain
Markdown files — though underline, text colour, and highlight formatting now
survive saving (see below).

---

## Fixed in 2.1.1

### Phantom empty blocks between paragraphs
The Markdown parser treated **every** blank line as an empty block, but the
serializer legitimately writes one blank line between paragraphs as a
separator. Result: a phantom empty block appeared between every two
paragraphs, reappeared after deletion, and *multiplied* on every save/load
cycle. The parser is now separator-aware: the first blank line after a
paragraph-style block is the separator; each **additional** blank line is a
deliberate empty block (after list items, which emit no separator, every
blank line counts). Files remain 100 % plain Markdown — no custom markers.

### Enter didn't split paragraphs
Pressing Enter mid-paragraph inserted an empty block below instead of
splitting. The block now splits at the caret — text after the caret moves
into the new block, inline formatting preserved on both sides. List
behaviours are unchanged (empty list item still turns back into text).

### Links weren't detected or clickable
Bare URLs typed or pasted into text are now recognised (on finishing the
word, on paste, and on blur), styled in the accent colour, and wrapped as
real links — clicking one opens it in a new tab. Existing pages with bare
URLs get linkified on render. Links already round-tripped to `[text](url)`
in the Markdown, so no format change.

### Delete at end of block
Forward-Delete at the end of a block now pulls the next block's content up
into it — the mirror of Backspace-at-start. Media blocks below are deleted
instead of merged; code blocks, databases, and toggles with children are
left untouched to avoid data loss.

### Right-click menus ran off screen
The block context menu always opened downward, so near the bottom of the
window it was partially hidden. Menus now measure their real height before
paint and flip above the cursor when there's no room below — submenus and
the new format menu included.

### Clicking the space below the last block
The large empty area under the last block (the editor's bottom padding) was
inert — only a thin 24 px strip was clickable. Clicking anywhere in that
space now places the caret at the end of the last block (or creates a fresh
paragraph if the page ends in an image, divider, etc.), and shows a text
cursor.

## New in 2.1.1

### Right-click formatting menu
Select text and right-click to get a Word-style mini toolbar: **Bold,
Italic, Underline, Strikethrough, Inline code**, a **Text colour** dropdown,
a **Highlight** dropdown (the same 10-colour, dark-mode-aware palette used
for block colours), and **Clear formatting**. The selection stays active so
formats can be chained. Right-click without a selection still opens the
block menu.

### Multi-block selection with the mouse
Dragging a text selection across a block boundary now switches to
whole-block selection (native selection can't span separate editable
blocks). Selected blocks are highlighted; **Backspace/Delete** removes them
(undoable), **Ctrl+C** copies their text, **Ctrl+X** cuts, **Escape** or a
click clears.

### Inline formatting that persists
Underline (a pre-existing bug — `<u>` was stripped on save), text colour,
and highlight now survive the save/load round-trip. They are stored as a
tiny HTML subset inside the Markdown (`<u>…</u>`,
`<span class="tc-red">…</span>`, `<span class="bg-yellow">…</span>`) —
readable in any editor and rendered by any HTML-aware Markdown viewer.
Chrome's `<strike>` output is now also converted to `~~…~~`.

## Running locally

```bash
npm install
npm run dev            # dev server — service worker disabled
# or, to exercise the PWA:
npm run build && npm run preview
```

No environment variables. Pick a **Local folder** (Chromium) or **Google Drive**
from the homepage.
